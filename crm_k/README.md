# Полное руководство по проекту (CRM)

Документ объясняет простым языком, что делает система, как она устроена и куда «идут» данные. Это единый файл‑справочник, к которому удобно обращаться каждый день.

## Что это
- CRM для центра занятий: расписание уроков, учет оплат, ученики, уведомления, WhatsApp.
- Две роли: Администратор и Преподаватель.
- Веб‑приложение на Next.js (один репозиторий и для фронта, и для API).

## Главные возможности
- **Расписание уроков**: календарь и список, фильтры по датам и статусам, печать расписания.
- **Ученики**: список, добавление/редактирование/удаление, фото, привязка к преподавателю.
- **Финансы**: оплаты и предоплаты, долги, выгрузка в XLSX/CSV, график выручки, печать отчетных блоков.
- **Уведомления**: напоминания перед уроками, ежедневные/еженедельные сводки, отправка через WhatsApp.
- **Админка**: управление пользователями, статистика, настройки системы, инструменты WhatsApp и Планировщика уведомлений.
- **AI‑подсказки**: генерация рекомендаций по занятиям для ученика (блок «AI Suggestions»).

## Дополнительные функции
- **Командная палитра** (Ctrl+K): быстрая навигация по всем разделам системы
- **Управление игрушками**: каталог игрушек с категориями (развивающие, сенсорные, моторные и др.)
- **Системные настройки**: конфигурация системы, темы, уведомления, безопасность
- **Аналитика и отчеты**: расширенная аналитика по всем аспектам работы центра
- **Логи безопасности**: мониторинг действий пользователей и системных событий
- **Управление балансами**: автоматический расчет и синхронизация балансов учеников
- **Swagger документация**: автоматическая генерация API документации (`/api/swagger`)
- **Публичные API**: бронирование занятий для внешних клиентов
- **Расширенные функции WhatsApp**: чаты, контакты, сообщения, история переписок

## Технологии
- Frontend: Next.js 15 (App Router), React 19, TypeScript, TailwindCSS 4.
- Backend: Next.js API Routes (внутри того же приложения).
- БД: SQLite + Prisma ORM.
- Аутентификация: JWT (токен в `localStorage`).
- Интеграции: `whatsapp-web.js`, экспорт XLSX (`xlsx`), диаграммы (`recharts`).

## Логика уроков: статусы и переходы

### Статусы уроков (7 основных состояний)
- **`scheduled`** (Запланировано) - урок создан, но еще не проведен и не оплачен
- **`prepaid`** (Предоплачено) - урок оплачен заранее, но еще не проведен
- **`completed`** (Проведено) - урок проведен, но еще не оплачен
- **`paid`** (Оплачено) - урок проведен и оплачен (финальное состояние)
- **`debt`** (Задолженность) - урок проведен, но не оплачен (долг)
- **`unpaid`** (Не оплачено) - урок прошел по времени, но не был проведен и не оплачен
- **`cancelled`** (Отменено) - урок отменен (финальное состояние)

### Детальная логика переходов с бизнес-правилами

#### 1. **SCHEDULED** (Запланировано) → может перейти в:

**🔄 Ручные переходы:**
- **PREPAID** - если получена предоплата (через форму "Добавить оплату")
- **COMPLETED** - если урок проведен без предоплаты (кнопка "Провести урок")
- **CANCELLED** - если урок отменен (кнопка "Отменить урок")

**⏰ Автоматические переходы (по времени):**
- **UNPAID** - если урок прошел по времени и не был проведен

**📋 Условия отмены:**
- Отмена возможна только если до урока осталось **≥ 5 часов**
- Если отмена **< 5 часов** - система не позволит отменить
- При отмене **≥ 5 часов** - сумма возвращается в предоплату ученика
- При отмене **< 5 часов** - сумма засчитывается как доход (но отмена запрещена)

---

#### 2. **PREPAID** (Предоплачено) → может перейти в:

**🔄 Ручные переходы:**
- **COMPLETED** - урок проведен (кнопка "Провести урок")
- **CANCELLED** - урок отменен (кнопка "Отменить урок")

**⏰ Автоматические переходы (по времени):**
- **PAID** - если урок прошел по времени и был предоплачен

**📋 Особенности:**
- При проведении урока (**COMPLETED**) автоматически становится **PAID**
- При отмене сумма остается в предоплате ученика
- Баланс ученика увеличивается на стоимость урока

---

#### 3. **COMPLETED** (Проведено) → может перейти в:

**🔄 Ручные переходы:**
- **PAID** - если получена оплата (через форму "Добавить оплату")
- **DEBT** - если оплата не получена (кнопка "Отметить как долг")

**📋 Особенности:**
- Этот статус временный - урок уже проведен
- Если был **PREPAID** → автоматически становится **PAID**
- Если был **SCHEDULED** → нужно вручную отметить оплату или долг

---

#### 4. **DEBT** (Задолженность) → может перейти в:

**🔄 Ручные переходы:**
- **PAID** - если получена оплата (через форму "Добавить оплату")

**📋 Особенности:**
- Уменьшает баланс ученика на стоимость урока
- Отображается в списке долгов на странице "Финансы"
- Можно экспортировать в отчеты по задолженностям

---

#### 5. **UNPAID** (Не оплачено) → может перейти в:

**🔄 Ручные переходы:**
- **PAID** - если получена оплата (через форму "Добавить оплату")
- **DEBT** - если урок был проведен, но не оплачен (кнопка "Отметить как долг")

**📋 Особенности:**
- Автоматически устанавливается для прошедших **SCHEDULED** уроков
- Уменьшает баланс ученика на стоимость урока
- Можно "исправить" - отметить как проведенный и оплаченный

---

#### 6. **PAID** и **CANCELLED** - финальные состояния

**✅ PAID (Оплачено):**
- Финальное состояние - дальнейших переходов нет
- Урок завершен успешно
- Не влияет на баланс ученика (нейтрально)

**❌ CANCELLED (Отменено):**
- Финальное состояние - дальнейших переходов нет
- Урок отменен
- Не влияет на баланс ученика (нейтрально)

### Детальное влияние на финансы

#### 💰 **Баланс ученика рассчитывается как:**
```
Баланс = Предоплаченные уроки - Задолженности

Где:
- Предоплаченные уроки = сумма всех PREPAID уроков
- Задолженности = сумма всех DEBT + UNPAID уроков
```

#### 📊 **Статусы и их влияние на баланс:**

**🟢 Положительное влияние (+ к балансу):**
- **PREPAID** - увеличивает предоплату на стоимость урока
- **Пример:** Урок стоимостью 1000₽ в статусе PREPAID = +1000₽ к балансу

**🔴 Отрицательное влияние (- к балансу):**
- **DEBT** - увеличивает задолженность на стоимость урока
- **UNPAID** - увеличивает задолженность на стоимость урока
- **Пример:** Урок стоимостью 1000₽ в статусе DEBT = -1000₽ к балансу

**⚪ Нейтральное влияние (0 к балансу):**
- **PAID** - урок завершен, не влияет на баланс
- **CANCELLED** - урок отменен, не влияет на баланс
- **SCHEDULED** - урок еще не проведен, не влияет на баланс

---

#### 🔄 **Примеры изменения баланса:**

**Сценарий 1: Успешный урок с предоплатой**
```
1. Создан урок SCHEDULED (1000₽) → Баланс: 0₽
2. Получена предоплата → PREPAID (1000₽) → Баланс: +1000₽
3. Урок проведен → PAID (1000₽) → Баланс: 0₽ (нейтрально)
```

**Сценарий 2: Урок без предоплаты**
```
1. Создан урок SCHEDULED (1000₽) → Баланс: 0₽
2. Урок проведен → COMPLETED (1000₽) → Баланс: 0₽
3. Оплата не получена → DEBT (1000₽) → Баланс: -1000₽
4. Получена оплата → PAID (1000₽) → Баланс: 0₽
```

**Сценарий 3: Отмена урока**
```
1. Создан урок SCHEDULED (1000₽) → Баланс: 0₽
2. Получена предоплата → PREPAID (1000₽) → Баланс: +1000₽
3. Урок отменен (≥5 часов) → CANCELLED (1000₽) → Баланс: 0₽
```

**Сценарий 4: Просроченный урок**
```
1. Создан урок SCHEDULED (1000₽) → Баланс: 0₽
2. Время урока прошло → UNPAID (1000₽) → Баланс: -1000₽
3. Получена оплата → PAID (1000₽) → Баланс: 0₽
```

---

#### 📈 **Финансовая отчетность:**

**Доходы (Revenue):**
- Все уроки в статусе **PAID** (проведенные и оплаченные)
- Отображается в графике выручки
- Экспортируется в отчеты

**Предоплаты (Prepayments):**
- Все уроки в статусе **PREPAID**
- Увеличивают баланс ученика
- Не считаются доходом до проведения урока

**Задолженности (Debts):**
- Все уроки в статусах **DEBT** и **UNPAID**
- Уменьшают баланс ученика
- Отображаются в списке долгов
- Экспортируются в отчеты по задолженностям

**Отмененные уроки:**
- Все уроки в статусе **CANCELLED**
- Не влияют на доходы или баланс
- Могут учитываться в статистике отмен

### Автоматические переходы и временные правила

#### ⏰ **Автообновление статусов прошедших уроков:**

**Триггер:** При загрузке страниц расписания, финансов или админки

**Логика автообновления:**
```
Если текущее время > время урока:
  ├─ Если статус PREPAID → автоматически PAID
  ├─ Если статус SCHEDULED → автоматически UNPAID  
  └─ Если статус COMPLETED → остается COMPLETED (требует ручного действия)
```

**Где происходит:** `src/app/api/lessons/auto-update-status/route.ts`

---

#### 🚫 **Правило отмены (5 часов):**

**Функция проверки:** `canCancelLesson(lessonDate, hoursBeforeLesson = 5)`

**Логика:**
```
Время до урока = время урока - текущее время
Если время до урока ≥ 5 часов:
  ├─ Отмена разрешена ✅
  ├─ Сумма возвращается в предоплату
  └─ Статус: SCHEDULED → CANCELLED
     PREPAID → CANCELLED

Если время до урока < 5 часов:
  ├─ Отмена запрещена ❌
  ├─ Кнопка "Отменить" неактивна
  └─ Система показывает предупреждение
```

**Где настраивается:** `src/lib/lessonStatusUtils.ts` (функция `canCancelLesson`)

---

#### 🔄 **Автоматические переходы по времени:**

**1. PREPAID → PAID (автоматически):**
- Условие: время урока прошло + статус PREPAID
- Действие: автоматически становится PAID
- Влияние на баланс: нейтрально (предоплата "закрывается")

**2. SCHEDULED → UNPAID (автоматически):**
- Условие: время урока прошло + статус SCHEDULED
- Действие: автоматически становится UNPAID
- Влияние на баланс: уменьшает баланс на стоимость урока

**3. COMPLETED → остается COMPLETED:**
- Условие: время урока прошло + статус COMPLETED
- Действие: статус не меняется (требует ручного действия)
- Влияние на баланс: зависит от дальнейших действий

---

#### 📊 **Временные окна для действий:**

**До урока (≥ 5 часов):**
- ✅ Можно отменить
- ✅ Можно изменить время
- ✅ Можно изменить ученика
- ✅ Можно изменить стоимость

**До урока (< 5 часов):**
- ❌ Нельзя отменить
- ✅ Можно изменить время (если новое время ≥ 5 часов)
- ✅ Можно изменить ученика
- ✅ Можно изменить стоимость

**После урока:**
- ❌ Нельзя отменить
- ❌ Нельзя изменить время
- ✅ Можно изменить статус оплаты
- ✅ Можно добавить комментарии

// В src/lib/lessonStatusUtils.ts
export function canCancelLesson(lessonDate: Date, hoursBeforeLesson: number = 5): boolean {
  const now = new Date();
  const timeDiff = lessonDate.getTime() - now.getTime();
  const hoursDiff = timeDiff / (1000 * 60 * 60);
  
  return hoursDiff >= hoursBeforeLesson;
}
```

  method: 'POST',
  headers: { 'Authorization': `Bearer ${token}` }
});
```

**2. Логика обновления:**
```typescript
// В src/app/api/lessons/auto-update-status/route.ts
const now = new Date();
const lessons = await prisma.lesson.findMany({
  where: {
    date: { lt: now },
    isCompleted: false,
    isCancelled: false
  }
});

for (const lesson of lessons) {
  if (lesson.isPaid) {
    // PREPAID → PAID
    await prisma.lesson.update({
      where: { id: lesson.id },
      data: { isCompleted: true }
    });
  } else {
    // SCHEDULED → UNPAID
    await prisma.lesson.update({
      where: { id: lesson.id },
      data: { /* статус остается SCHEDULED, но логически UNPAID */ }
    });
  }
}
```

**3. Обновление балансов:**
```typescript
// После изменения статусов уроков
await updateStudentBalance(lesson.studentId);
```

## Уведомления и WhatsApp (как это работает)
1) Настройки уведомлений на пользователя: таблица `NotificationSettings` (включить/выключить, за сколько минут, шаблоны, ежедневные/еженедельные сводки).
2) Планирование:
   - При создании урока API может поставить напоминание в `ScheduledNotification` на время `lessonTime - reminderBeforeLessons`.
   - Есть ручные эндпоинты для планирования ежедневных/еженедельных сводок.
3) Воркер: `NotificationWorkerService` периодически (по умолчанию каждые 5 минут) читает `ScheduledNotification` и отправляет их через WhatsApp API, отмечает статусы/ошибки.
4) WhatsApp API (`/api/whatsapp`):
   - `GET?action=init` — инициализация клиента; вернет QR (сканировать в WhatsApp).
   - `GET?action=status` — готов ли клиент, и есть ли QR.
   - `POST { action: 'send', phoneNumber, message }` — отправка сообщения.
   - Дополнительно: `chats`, `contacts`, `messages` для отладки.
5) Пуш‑обновления: есть SSE‑маршрут `/api/whatsapp/websocket` (сердцебиения/heartbeats для «живости»).

Где смотреть и менять
- Воркер: `src/lib/notification-worker.ts` (интервал, обработка, логгирование).
- Планирование уведомлений: `src/app/api/notifications/schedule/route.ts`.
- Эндпоинты управления воркером/настройками: `src/app/api/notifications/*`.
- WhatsApp API: `src/app/api/whatsapp/route.ts`.

Примечания
- Отправка идет через локальный WhatsApp Web (пакет `whatsapp-web.js`). Нужна один раз авторизация по QR.
- Если клиент не готов, воркер не отправит и оставит запись с ошибкой — можно повторить позже.

## Аутентификация и доступ
- Логин: `/api/auth/login` (результат — пользователь и JWT токен). Токен сохраняется в `localStorage` (`user`, `token`).
- Роли: `ADMIN` видит все; `USER` работает в пределах своих данных. Многие API автоматически фильтруют по `teacherId` для пользователя.
- В React используется `AuthContext` для состояния входа и передача токена в `apiRequest`.

Где смотреть и менять
- Логин API: `src/app/api/auth/login/route.ts`.
- Разбор JWT из запроса: `src/lib/auth.ts`.
- Фронтовый контекст: `src/contexts/AuthContext.tsx`.

## Поток данных (из кнопки до БД)
- Компонент на странице вызывает `apiRequest('/api/...')` и передает Bearer‑токен.
- API‑маршрут (Next.js) проверяет токен, собирает `where`/`data`, обращается к Prisma.
- Prisma пишет/читает в SQLite и возвращает результат обратно в компонент, где интерфейс обновляет список/вид/графики.

## Переменные окружения
- `DATABASE_URL` — путь к SQLite базе.
- `JWT_SECRET` — секрет для подписи JWT.
- `NEXT_PUBLIC_BASE_URL` — базовый URL для внутренних вызовов из воркера (по умолчанию `http://localhost:3000`).
- `GEMINI_API_KEY` — API ключ для Google Gemini (AI-подсказки).
- `NODE_ENV` — окружение (development/production).

## Советы по отладке
- **Авторизация**: убедитесь, что `JWT_SECRET` задан и токен попадает в заголовок `Authorization: Bearer ...`.
- **База**: путь `DATABASE_URL` корректный, миграции применены, сид выполнен.
- **WhatsApp**: сначала инициализируйте и отсканируйте QR; проверяйте `/api/whatsapp?action=status`.
- **Уведомления**: если воркер сообщает, что клиент не готов — он повторит позже; ошибки видны в `scheduled_notifications.errorMessage`.
- **Swagger**: спецификация доступна по `/api/swagger`, UI — страница `src/app/api-docs/page.tsx`.
- **AI-подсказки**: проверьте `GEMINI_API_KEY` в переменных окружения; ошибки видны в консоли браузера.
- **Балансы**: если балансы не обновляются, используйте кнопку "Синхронизировать балансы" в админке.
- **Командная палитра**: если не работает, проверьте консоль браузера на ошибки JavaScript.
- **Игрушки**: если не отображаются, проверьте подключение к базе данных и миграции.
- **Аналитика**: если графики не загружаются, проверьте API эндпоинты `/api/finances/stats` и `/api/admin/stats`.
- **Логи безопасности**: если логи не отображаются, проверьте права доступа и подключение к базе.
