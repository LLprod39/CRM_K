# Логика конфликтов занятий

## Обзор

Система проверки конфликтов занятий предотвращает создание занятий, которые нарушают бизнес-правила организации.

## Правила конфликтов

### 1. Ограничение количества учителей
**Правило:** Больше двух учителей не могут заниматься одновременно в одно и то же время.

**Реализация:** 
- При создании/обновлении занятия система проверяет количество уникальных учителей, занятых в указанное время
- Если уже заняты 2 или более учителя, создание нового занятия блокируется

**Пример ошибки:**
```
В это время уже заняты 2 учителя: Учитель 1, Учитель 2
```

### 2. Ограничение групповых занятий
**Правило:** Групповое занятие не может включать более 2 детей на одного учителя.

**Реализация:**
- При создании группового занятия проверяется количество учеников
- Если указано более 2 учеников, создание блокируется
- Также проверяется, нет ли уже групповых занятий у учителя в это время

**Пример ошибки:**
```
Групповое занятие не может включать более 2 детей
У учителя уже есть групповые занятия с 2 детьми в это время: Иван, Мария
```

### 3. Конфликты пользователей
**Правило:** Если у пользователей уже есть занятия в указанное время, система не даст записать на это время.

**Реализация:**
- Система группирует учеников по их владельцам (пользователям)
- Для каждого владельца проверяется наличие существующих занятий в указанное время
- Если найдены конфликты, создание блокируется

**Пример ошибки:**
```
У пользователя Иван Петров уже есть занятия в это время: Анна Петрова
```

### 4. Обеденные перерывы
**Правило:** Занятия не могут проводиться во время обеденных перерывов учителя.

**Реализация:**
- При создании занятия проверяется пересечение времени с обеденными перерывами учителя
- Если время пересекается с обедом, создание блокируется

**Пример ошибки:**
```
Слот недоступен: Время пересекается с обеденным перерывом (12:00 - 13:00)
```

## Освобождение слотов

### При удалении занятий
При удалении занятия система автоматически освобождает временной слот для других записей.

### При удалении обеденных перерывов
При удалении обеденного перерыва система освобождает временной слот для записи занятий.

## API Endpoints

### Создание занятий
- `POST /api/lessons` - создание одного занятия
- `POST /api/lessons/bulk` - массовое создание занятий

**Ответ при конфликте:**
```json
{
  "error": "Конфликт времени занятий",
  "details": [
    "В это время уже заняты 2 учителя: Учитель 1, Учитель 2"
  ]
}
```

### Обновление занятий
- `PUT /api/lessons/[id]` - обновление занятия

**Проверка конфликтов:** Выполняется только при изменении времени или учителя.

### Удаление занятий
- `DELETE /api/lessons/[id]` - удаление занятия

**Автоматическое освобождение:** Слот автоматически освобождается после удаления.

### Удаление обеденных перерывов
- `DELETE /api/lunch-breaks` - удаление обеденного перерыва

**Автоматическое освобождение:** Слот автоматически освобождается после удаления.

## Использование в коде

### Проверка конфликтов
```typescript
import { checkLessonConflicts } from '@/lib/lessonConflictUtils'

const result = await checkLessonConflicts({
  date: new Date('2024-01-15T10:00:00Z'),
  endTime: new Date('2024-01-15T11:00:00Z'),
  teacherId: 1,
  studentIds: [1, 2],
  lessonType: 'group'
})

if (!result.canCreate) {
  console.log('Конфликты:', result.conflicts)
}
```

### Проверка доступности слота
```typescript
import { checkSlotAvailability } from '@/lib/lessonConflictUtils'

const result = await checkSlotAvailability(
  teacherId,
  lessonDate,
  lessonEndTime
)

if (!result.isAvailable) {
  console.log('Причина:', result.reason)
}
```

### Освобождение слота
```typescript
import { releaseSlot } from '@/lib/lessonConflictUtils'

await releaseSlot(teacherId, lessonDate, lessonEndTime)
```

## Обработка ошибок в UI

Формы автоматически отображают детальные ошибки конфликтов:

```typescript
if (errorData.details && Array.isArray(errorData.details)) {
  // Показываем детальные ошибки конфликтов
  setError(errorData.details.join('; '));
} else {
  setError(errorData.error || 'Ошибка при создании занятия');
}
```

## Логирование

Система логирует освобождение слотов для мониторинга:

```
Слот освобожден для учителя 1: 2024-01-15T10:00:00.000Z - 2024-01-15T11:00:00.000Z
```
